# Screen: Dashboard (`/dashboard` in the web UI; a static build variant exists via `oxe stats build`)

In the web UI, `/dashboard` is a live route sharing the app header
(oxe / search / history / dashboard / (?) / settings / GitHub /
version). It fetches cache stats from `GET /cache/stats` and renders a
responsive panel grid. Log-derived panels (searches per day, network
latency, client split) show a muted "no search log data yet" placeholder
until the backend exposes a stats endpoint. A fully static, no-JS
dashboard generated by the `oxe stats build` CLI remains available as a
separate artifact.

Static build variant (`oxe stats build` -> `dist/dashboard/index.html`)
keeps the original panel set: searches/day (cache vs network stacked),
cache hit rate with trend sparkline, network latency p50/p95, client
split bars, top-20 queries, zero-result queries list, all baked into
inline SVG at build time.

## Behavior

- Live route: panels fetch `GET /cache/stats` on mount and show the
  cache hit-rate percentage (unexpired/rows), total hits, and a cache
  table (rows, unexpired, db size, newest). Fetch errors render in the
  panel body.
- Panels without a data source render a flat muted "no search log data
  yet" line instead of an empty chart; the page still renders.
- Log-derived panels become real charts once the backend ships a stats
  JSON endpoint; no route changes expected.
- Static build variant: fully self-contained (inline SVG charts, no
  JS, no external requests), works from `file://`, header shows tool
  name, generation timestamp, and the build-time stats window (e.g.
  `last 30 days`). Changing the window means re-running the build.
## Responsive

- Panel grid: `repeat(auto-fit, minmax(20rem, 1fr))` — multi-column on
  desktop, single column stacked below ~700px. Always full width.
## Notes

- Static build command: `oxe stats build` writes
  `dist/dashboard/index.html`. DB access is read-only and WAL-safe
  (opens the sqlite file in RO mode so it never contends with the
  running proxy).
- The static build is stdlib only: no chart library, no template engine
  beyond `string.Template`, no JS emitted at all. Regenerate on demand
  or from a cron; the page always reflects the state of `search_log` at
  build time.
- The live `/dashboard` route reuses the app design tokens and header;
  it is the screen QA agents interact with.
