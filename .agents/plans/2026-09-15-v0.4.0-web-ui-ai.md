# oxe v0.4.0 — Web UI + AI Search Implementation Plan

Date: 2026-09-15
Status: approved for execution (pending final owner sign-off)
Specs: `.agents/docs/screens/{landing,search,history,dashboard}.md`
Stack decision: `.agents/drafts/tech-stack.md`; AI layer: memory `v04-ai-stack-decision.md`

## Goal

Ship v0.4.0: a redesigned web UI (classic search + AI search modes) built as a
separate Preact + Vite + daisyUI app under `ui/`, served by the backend from
build output, plus an AI answer pipeline powered by aisuite. Legacy `oxe/static`
templates are deleted entirely (replace, not fallback).

## Constraints (binding)

1. Zero-conf `oxe` default: web search + UI + cache + MCP baked in, enabled by default.
2. Web UI is SSG/CSR with 0 runtime impact when unused.
3. AI mode hidden unless an LLM is configured.
4. RSS baseline (~70MB) uncompromised; AI deps behind the `oxe[ai]` extra, lazily imported.
5. UI never hand-rolled HTML: design token system = daisyUI 5 on Tailwind 4; components from libraries preferred; custom logic modularized on top of tokens.
6. Every UI stage verified responsive at ~390px mobile viewport before done.
7. Conventional commits, atomic per logical change. No co-author trailers.

## Architecture

```
oxe/            backend Python package (PyPI); server, cache, MCP, AI pipeline
ui/             Preact + Vite + daisyUI app; NOT shipped; build output -> served
mise.toml       tooling: python + bun, lifecycle tasks (dev/build/serve/check/lint/test)
```

- AI provider layer: `aisuite[openai,anthropic]` pinned, manual streaming tool loop.
  We drive ReAct iterations (max 5) + confidence threshold (8/10) and emit SSE
  tool-step events ("searching..."). `/v1/models` uses direct provider SDK calls
  (aisuite has no unified listing).
- Settings: config file is source of truth; settings dialog reads/writes it.
  valibot schema + uncontrolled form, parse-on-submit.
- Agent tools (`exa_search`, `exa_user_history`) gain `source=web|history|cache`
  on the web_search tool; completed AI answers are cached.
- Suggestions: `GET /suggest` (OpenSearch Suggestions JSON), LIKE prefix match,
  ranked recency→frequency, local search_log always-on (cap 3, dedup), 300ms
  debounce, keyboard nav.
- SSE streaming via StreamingResponse for AI answers.

## Stages

### Stage 1 — Tooling + scaffolding
- `mise.toml`: python + bun latest, tasks (dev/build/serve/check/lint/test) for both `oxe/` and `ui/`.
- Scaffold `ui/` (Vite + Preact + TS), Tailwind 4 + daisyUI 5, file-based routing,
  feature-driven dirs, component SRP. Size budgets: 30KB gz CSS / 40KB gz JS.
- Python tooling stays lean: ruff + pytest only.
- First `ui/AGENTS.md` compliance pass (tokens-first, no vanilla HTML).
- Commit(s): chore(tooling), feat(ui-scaffold).

### Stage 2 — Classic search screens (UI)
Implement landing + search + history + dashboard screens from specs
(`.agents/docs/screens/*.md`), wired to existing `/search`, `/history`, `/suggest`.
- **Generator/validator loop**: generator uses high-end-visual-design skill;
  validator runs ux-audit skill against the RENDERED UI in a browser
  (plus 2nd-order code review). Max 5 iterations, pass threshold 8/10.
- Mobile check at ~390px each iteration.
- Backend: add `/suggest` endpoint + search_log writes if missing.
- Delete `oxe/static` legacy templates at the END of this stage, once UI serves.

### Stage 3 — AI pipeline (backend)
- `oxe[ai]` extra: `aisuite[openai,anthropic]` pinned.
- Provider layer: manual streaming tool loop (search tool with
  `source=web|history|cache`), max_iter 5, confidence ≥8/10, SSE events.
- Config file schema (source of truth) + `/v1/models` via direct SDK calls.
- Cache completed AI answers; AI mode hidden when no LLM configured.
- Lazy imports everywhere; verify RSS impact stays in budget.
- MCP wiring unchanged; cached answers shared HTTP/MCP.
- Tests: unit for loop + config; smoke test pinning aisuite behavior
  (regression refs #266/#295).

### Stage 4 — AI mode UI
AI answer surface in the search screen per `search.md`: streaming answer,
tool-step indicators, source cards, related questions, completed-answer cache
hits. Same generator/validator loop (max 5, 8/10), mobile check.

### Stage 5 — Settings dialog
Web settings dialog reading/writing the config file; valibot + uncontrolled
form parse-on-submit (formisch only if per-field errors prove needed);
model picker fed by `/v1/models`. Generator/validator loop, mobile check.

### Stage 6 — Hardening + release
- Full backend test suite + lint + typecheck green; UI lint/check green.
- RSS measurement vs 70MB baseline (with and without `oxe[ai]`).
- Size-budget check on built UI assets.
- README/AGENTS.md updates (endpoints table, `oxe[ai]` install, env vars).
- Version bump to 0.4.0, conventional-commit history clean, tag.

## Verification gates (per stage)

| Gate | How |
|---|---|
| Lint/format | mise task `check` (ruff+pytest / oxlint+oxfmt) |
| UI quality | generator/validator loop ≥ 8/10, ≤5 iters |
| Responsive | manual/automated pass at 390px |
| RSS | measured, documented at stages 3 and 6 |
| Payload | gz size budget at stages 1, 2, 4 |

## Risks

- aisuite 0.1.x churn: pin + smoke tests; fallback = smolagents custom (+41MB).
- No unified model listing: accepted, direct SDK calls for `/v1/models`.
- Extended/thinking mode deferred to v0.5 (near-trivial via reasoning_effort passthrough if time allows).
