## TL;DR

oxe v0.4.0 (current) is a search proxy with a single-shot ReAct loop. The fundamental gap to Perplexity/Gemini/ChatGPT-quality is **three-layer**:

1. **The search layer returns DDG snippets**, not pages — and the LLM cites what it's given.
2. **The tool loop is sequential, sync, single-round** — no parallelism, no planner, no per-round source reveal.
3. **The product is invisible to AI harnesses** — no stdio MCP transport, no paste-ready `.mcp.json`, MCP `instructions` reads as a contract not a pitch.

Layer 1 is the foundation. Everything else slots in on top.

Suggested v0.5.0 ships these 10 PRs in this order:

1. **PR-A** — chmod 600/700 on cache & config dirs (security baseline, S).
2. **PR-B** — page-content fetcher + second tool `web_fetch` + MCP `exa_get_contents` (foundation).
3. **PR-C** — meta-description snippet + freshness metadata + `startPublishedDate` honoring.
4. **PR-D** — answers_log table + per-step latency events + provider-error class + live dashboard.
5. **PR-E** — stdio MCP transport + paste-ready `.mcp.json` + rewritten `instructions` string.
6. **PR-F** — empty-results-vs-error plumbing (smoke PR).
7. **PR-G** — parallel tool loop + default fallback backend + retry-with-rebuild on rate-limit.
8. **PR-H** — re-rank (authority tiers + dedupe + technical-query bias) + cache-poisoning guard.
9. **PR-I** — MCP `exa_answer` + URL normalization + cached-`/answer` SSE delta fix.
10. **PR-J** — History URL state + copy/regenerate in Answer view (UI polish).

Net effect: oxe goes from "search proxy with single-shot ReAct" to "agent-native answer engine with full-text extraction, parallel research, MCP parity with Jina/Tavily, paste-ready install, deep-linkable UI, and a maintainer who sees problems before users report them."

## Consolidated prioritized changes (10 PRs)

Each PR has: scope, file:line seam, dependencies, effort, ROI notes.

### PR-A — chmod 600/700 on cache & config dirs (security baseline)

**Priority:** ship first; tiny standalone PR.

**Scope (exclusive):**
- `oxe/cache.py:23-30` — after `parent.mkdir(parents=True, exist_ok=True)`, `os.chmod(parent, 0o700)`; create `cache.db` via `os.open(path, O_CREAT | O_WRONLY, 0o600)` to avoid the race.
- `oxe/config.py:80-85` — same on `OXE_CONFIG_DIR` and `config.toml`.
- Idempotent reset on write: `cache.put`, `config.save_config`.
- 1-line AGENTS.md note: "Cache lives at `$OXE_CACHE_DIR/cache.db`, always owner-only (chmod 600)."

**Why this lands first:** two-file PR, no schema, no behavior change. Defensible even in solo use. Solves the "logs leaked in a screenshot" path. Closes the highest severity pair in the privacy POV.

**Effort:** S. **ROI:** security hardener for shared-host (CI, agent dev boxes).

### PR-B — page-content fetcher (foundation)

**Depends on:** none (composes with PR-C later).

**Scope:**
- New `oxe/fetch.py` with `extract(url, timeout=5.0) -> str` (trafilatura with description fallback).
- Add `trafilatura>=1.6` to `pyproject.toml` `[project.optional-dependencies] ai`.
- `oxe/ai.py:53-97` `TOOLS_SPEC`: add a second tool `web_fetch(url: str)` returning `{url, text: <extracted body truncated to 2k chars>, status}`.
- `oxe/ai.py:108-127` `web_search` tool: when AI mode, append extracted text for top 3 results into the tool-result payload (truncate per-doc 2k chars, total budget 8k) — but only after the per-URL cache from PR-C is in place.
- `oxe/mcp_server.py` (line 32 area): add `@mcp.tool(name="exa_get_contents", description="fetch and extract page body from one or more URLs")` wrapping `oxe/fetch.extract`.
- New `oxe/sql/fetches.sql` (+ table in schema.sql) — per-URL extracted body cache, TTL 7 days, keyed by `sha256(url)`.
- HTTP `/search` payload stays snippet-only (don't bloat). Extraction only happens inside the AI pipeline or via `exa_get_contents`.

**Why this is foundation:** every other gap (better citations, freshness depth, multi-query research) hits a ceiling if the model can't read pages it cites. Two tools (`web_search` + `web_fetch`) instead of fusion: lets the model be smart about when to spend tokens on a full read.

**Effort:** L. **ROI:** highest; closes Perplexity POV-4 (severity 9), agent-dev #1 (severity 7), Perplexity POV-9 indirectly.

### PR-C — meta-description snippet + freshness metadata

**Depends on:** PR-B (reuses per-URL cache layer).

**Scope:**
- New `oxe/snippet.py::extract_meta(html) -> str`: pulls `<meta name="description">` or first `<p>` content (~300 chars). Replaces DDG `body` with this cleaner snippet.
- `oxe/exa_compat.py:67-84` `_dgr_to_exa`: in addition to DDG `body`, run parallel `httpx.AsyncClient().head(url, timeout=2)` for top 5 results. Parse `<meta property="article:published_time">` / `<meta name="pubdate">` / `<time datetime>` / JSON-LD `datePublished`; populate `publishedDate` when found, leave `None` when not (don't lie).
- `oxe/exa_compat.py:53-57` `_extract_highlights`: replace first-3-sentences-blindly with query-term TF-IDF scoring; set `highlightScores` to real scores; add `_snippet_origin: "first3"|"scored"`.
- New `oxe/query.py::time_sensitive(q: str) -> bool`: regex `\b(latest|today|breaking|this week|yesterday|20\d{2}|news)\b`. When true, set `timelimit="w"` or `"d"` automatically in `exa_compat.search`.
- Honor `startPublishedDate`/`endPublishedDate`: map to DDG `timelimit`/`df` range; include dates in `cache_key` (line 20-38) so dates don't serve stale filtered results.
- Add `OXE_FAVICON_PROVIDER=ddg|google|none` env (privacy POV-1 fix); default `ddg`. Update `_dgr_to_exa` line 16 to consult this var.

**Why this lands after PR-B:** PR-B establishes the per-URL fetch infra (httpx client, cache table). Reuses that infra for the parallel HEAD fetches here. Share `oxe/snippet.py::extract_meta` between fetcher (PR-B) and snippet enrichment (PR-C).

**Effort:** M. **ROI:** search POV-1 (severity 8) + POV-3 (severity 8) — the "trust axis" for citation freshness.

### PR-D — answers_log + per-step latency + provider-error class + live dashboard

**Depends on:** none. Standalone observability PR.

**Scope:**
- New `oxe/sql/answers_log.sql` table: `(id, ts, query_text, query_hash, model, confidence, n_steps, duration_ms, error_class, client)`. Migration in `oxe/sql/migrations/0001_answers_log.sql`.
- `oxe/cache.py::TTLCache.log_answer(...)` — append helper.
- `oxe/ai.py::stream_answer` (line 396-445): after terminal yield, call `c.log_answer(...)`. Same in cached path `server.py:474-489`.
- `oxe/ai.py::stream_answer` (line 390-410): emit `_dev_event("ai.tool_call", tool=..., query=..., duration_ms=..., results=N)` around each tool dispatch.
- `oxe/ai.py::_friendly_provider_error` (line 464-480): the `try/except` at line 288-298 derives `error_class = re.search(r'\b(401|404|429|402|timeout)\b', str(e).lower())` and includes it in `_dev_event("answer", error_class=...)`. NOT in the SSE user message (just the friendly string).
- New `oxe/sql/search_log.sql`: add `stat-backend-split(cutoff)` GROUP BY `backend`.
- `oxe/stats.py:297-345` `build_json`: include `error_class_breakdown` and `answers_log` slice.
- `ui/src/lib/api.ts:144`: add `export async function apiStats()` hitting `GET /api/stats`.
- `ui/src/routes/dashboard.tsx:25-43`: rewrite four panels to consume `apiStats()`; add 30s polling and "last refreshed" stamp. Drop the obsolete "no search log data" comment.

**Why standalone:** observability is a hard prerequisite for confident shipping. Once answers_log exists + dashboard is live, the maintainer sees "answers are flaky today" in stats before the user complains.

**Effort:** S-M. **ROI:** obs POV-5 (severity 9), addresses the silent-cache-poisoning-via-low-confidence failure mode.

### PR-E — stdio MCP transport + paste-ready `.mcp.json` + rewritten `instructions`

**Depends on:** none (although PR-D's observability helps debug).

**Scope:**
- `oxe/__main__.py:21-38`: add `--mcp` and `--transport=stdio` flag handling. When set, skip uvicorn and call `mcp_server.mcp.run(transport="stdio")` (the `mcp` Python lib exposes this directly).
- `oxe/mcp_server.py:21-28` `instructions`: lead with the value:
  > "Free local Exa.ai-compatible web search backed by DuckDuckGo + cached. Same response shape as Exa's `/search` endpoint, no API key. Call `exa_user_history` BEFORE `exa_search` to discover what the user has already read in the web UI. Both tools share a 1h TTL SQLite cache (replays are instant)."
- New `docs/mcp-clients.md`: three paste targets (Claude Code, Cursor, maki/Hermes):
  ```json
  // ~/.claude/.mcp.json or ~/.cursor/mcp.json
  {
    "mcpServers": {
      "oxe": { "command": "uvx", "args": ["oxe", "--mcp"], "transport": "stdio" }
    }
  }
  ```
  Plus URL-based alternative (`{"url": "http://127.0.0.1:4479/mcp/"}`).
- README "MCP clients" section linking to that doc.
- `oxe/config.py` + `ui/src/features/settings/SettingsDialog.tsx`: sync the provider list with backend (`schema.ts:14` vs `config.py:31`). Add `openrouter` to `VALID_PROVIDERS` (already used in `ai.py:356` failure path).
- One-line notice on first AI-mode open: "AI sends queries + click history to provider X (opt out: `OXE_AI_DISABLE_HISTORY_TOOL=1`)."

**Why this lands before PR-F (error plumbing):** distribution POV-5 names it the install-to-daily-use moment; security POV-2 wants the same transparency on first AI enable. Together they answer "what does Claude Code see when I install oxe?"

**Effort:** M. **ROI:** conversion-funnel.

### PR-F — empty-results-vs-error plumbing (smoke PR)

**Depends on:** none (one-file change + UI tweak).

**Scope:**
- `oxe/exa_compat.py:150-153`: when `raw` is empty AND `last_err is not None`, return `{"results": [], "_error": str(last_err)[:200], "_error_kind": "upstream"}`.
- `oxe/backends.py:154` `FallbackBackend.search`: include the failed backend's error in the payload when the whole chain fails.
- `X-Cache: HIT | MISS` header on `/search` (`oxe/server.py:205-242`).
- Extend pydantic `ExaRequest` response model to admit `_error`, `_error_kind`, `_duration_ms`, `_cached_at`.
- `ui/src/routes/search.tsx:206-225`: surface `_error` (already has retry + ask-AI; add a "DDG is rate-limited — try again" line).

**Why standalone:** the most-cited blocker by agent-devs. Ship fast and alone.

**Effort:** S. **ROI:** highest debug-cost-reduction for every integrating agent.

### PR-G — parallel tool loop + default fallback backend

**Depends on:** PR-D (so we can measure impact) + PR-F (errors visible).

**Scope:**
- `oxe/ai.py:390-410` tool loop: change `for tc in tool_calls:` to `await asyncio.gather(*[asyncio.to_thread(fn, **args) for tc in tool_calls])`. Then append results in tool_call_id order to preserve the conversation contract. Reuse `concurrent.futures.ThreadPoolExecutor(max_workers=4)` at module scope.
- `oxe/registry.py:84-98`: when `OXE_BACKENDS` is unset, return `FallbackBackend([DdgsBackend("ddg"), DdgsBackend("wikipedia"), DdgsBackend("bing")])` instead of bare `DDGBackend()`. The composers are battle-tested (`backends.py:127-195`), and per-engine cache namespacing already isolates results.
- Add `OXE_AI_MAX_ITERATIONS` env override + `max_iterations` field on `AIConfig` (`config.py:34`); read in `server.py:497` and pass to `stream_answer`. Default 5; for "deep research" prompts allow 8.
- `OXE_AI_CONFIDENCE_THRESHOLD` env override + `confidence_threshold` field; default 8.
- New `test_parallel_tool_calls` (`tests/test_ai_pipeline.py`): use a `time.sleep` fixture to assert gather semantics.
- New `test_fallback_default` (`tests/test_backends.py`): assert `build_from_env()` returns `FallbackBackend` when env unset.

**Effort:** M. **ROI:** lat-equivalent-of-3-5x speedup on multi-search answers (Perplexity POV-10 severity 7, engineering POV severity 6).

### PR-H — re-rank + dedupe + technical-query bias + cache-poisoning guard

**Depends on:** PR-C (freshness + snippet enrichment done first; rerank benefits from the per-URL metadata cache).

**Scope:**
- New `oxe/rerank.py` post-processor invoked from `exa_compat.search` after `_dgr_to_exa`:
  - Static authority tier dict: Tier 0 boost (`github.com`, `stackoverflow.com`, `docs.python.org`, `developer.mozilla.org`, `arxiv.org`, `*.wikipedia.org`, `*.gov`, `acm.org`, `ieee.org`, `nature.com`, `sciencedirect.com`); Tier 2 demote (`best-`, `-review-`, `top-10-`, `medium.com/?source=` substring match).
  - Near-dup dedupe: URL host normalization (strip `www.`, lowercase), track-param strip (`utm_*`, `fbclid`, `gclid`), merge duplicate `(reg-domain, path-prefix)` keeping the first-ranked.
  - Query-class bias: regex `\b(regex|equivalent of|how to (use|implement|write)|example|api|tutorial)\b` → prepend `OR (site:github.com OR site:stackoverflow.com OR site:docs.python.org OR site:developer.mozilla.org)` to `build_query`.
- Cache-poisoning guard in `oxe/cache.py::set` (line 54-66): on write, drop URLs whose registrable domain matches `oxe/data/blocklist.txt` (curated Spamhaus-style, ~30 entries). Enforce `max 30% same registrable domain` floor across the result list.
- `oxe/data/trusted_domains.txt` + `oxe/data/blocklist.txt` (small files shipped in package-data).
- UI: `ui/src/features/search/ResultCard.tsx` — small tier badge for trusted domains (reuses authority-tier dict via new `/api/authority` endpoint or just client-side static import).

**Effort:** M. **ROI:** search POV-2 (severity 7) + POV-13 (severity 7), addresses "agent cited SEO spam" complaint.

### PR-I — MCP `exa_answer` + URL normalization + cached `/answer` SSE delta fix

**Depends on:** PR-E (stdio MCP transport so new tools reach Claude Code).

**Scope:**
- `oxe/mcp_server.py:32` area: add `@mcp.tool(name="exa_answer", description="server-orchestrated streaming answer with cited sources; returns final {answer, sources, related_questions, confidence}")`. Reuse a thin sync wrapper of `stream_answer` that consumes all events and returns the terminal `done` payload (cap at `max_iterations=5`).
- New `oxe/exa_compat.py::normalize_url(url) -> str`: tracking-param stripper + lowercase host + drop fragment. Apply in `_dgr_to_exa` (`url = normalize_url(href)`, `id = url`), `oxe/cache.py::record_click` (so click history keyed by canonical URL), `_sources_from_messages` (dedup by canonical URL, `oxe/ai.py:224-241`).
- `oxe/server.py:480-489` `_cached_stream`: emit a synthetic `{"type":"delta", "text":""}` event before `sources` so consumers that wait for `delta` don't hang on the cached path.
- New `OXE_MCP_TOOLS=all|search+answer|answer+fetch|...` env to gate the new tools behind opt-in (downstream consumers pinned to the old 2-tool schema).

**Effort:** M. **ROI:** closes the Jina/Tavily MCP surface gap; makes the `/answer` HTTP path usable as an MCP tool.

## Risk register (cross-PR)

| Risk | Mitigation |
|---|---|
| PR-B (fetcher) adds a network dependency on every search | Cache in `fetches` table with TTL 7d; concurrent HEAD on top-3 only; respect `OXE_FETCH_DISABLED=1` opt-out |
| PR-G parallelization lets the LLM emit tool calls that DDG can't honor | Cap gather at `max_workers=4`; existing per-call timeout enforced |
| PR-H tier dict goes stale (new authoritative domains appear) | Ship as data file, not source — easy to update; document in `data/README.md` |
| PR-E stdio MCP transport breaks Claude Code users who pinned daemon URL | Detect via `__main__.py` argument; `oxe` without `--mcp` keeps HTTP daemon behavior |
| PR-D answers_log grows unbounded | `cache.prune_answer_log(retention_days)` task on startup, mirroring `prune_search_log` |
| PR-H near-dup dedupe mis-merges canonical different URLs | Conservative normalization (registrable-domain + path-prefix up to depth 3) + opt-out via `OXE_DEDUPE=off` |
| First-paint regression from new SPA panels in PR-D | `apiStats()` is on-demand at 30s; dashboard route already a lazy mount |

## Implementation cadence

Two-week sprint per PR. The order is sequenced so each PR is independently mergeable:
- PR-A ships day 1 alone (security quick win).
- PR-B is the longest (foundation).
- PR-C and PR-D can run in parallel after PR-B merges.
- PR-E is standalone (Claude Code distribution).
- PR-F is smoke between bigger features.
- PR-G depends on PR-D for measurement.
- PR-H depends on PR-C for metadata.
- PR-I depends on PR-E for stdio transport.
- PR-J depends on PR-D (proves the dashboard pattern).

Total estimate: ~10 weeks for one engineer at 50% capacity; ~5 weeks at 100%.
