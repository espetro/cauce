# Terminal UI (`cauce tui`)

A terminal search UI shipped inside the existing `cauce` binary, feature-gated like `mcp`.
In-process first: the TUI drives `SearchPipeline`/`SqliteStore` directly — the same bootstrap
`cauce search` uses — so `cauce tui` works with no server, no port, and warms the shared cache.

Exploration + Rust-vs-TS decision record: issue #285 (session report). Summary: TypeScript was
rejected for this surface — a TS TUI is remote-only (needs `cauce serve` running, the case
where a TUI adds least), needs a second toolchain/runtime the workspace doesn't have, and its
attractive libraries are either FFI-bound through an experimental compiler (scriptc — island
marshalling limits already hit in nostream work) or 0.1.x (OpenTUI). A remote-only
standalone-client product could revisit TS+OpenTUI; `cauce tui` the subcommand should be Rust.

## Design

```
cauce tui [query]        → LocalBackend: SearchPipeline in-process (default)
cauce tui --remote <url> → RemoteBackend: reqwest + SSE (later phase)
```

- `SearchBackend` seam: `search_stream`, `suggest`, `answer` (the last gated on `ai`,
  unimplemented until the answer phase). MVP ships LocalBackend only.
- Rendering: `ratatui` + `ratatui-crossterm` (0.30 backend split). `TestBackend` for headless
  unit tests of the render/dedupe logic — matches the golden-path test style.
- Streaming model: `SearchPipeline::search_stream` emits `StreamEvent::Results{engine,…}`
  batches per engine and a terminal `Meta` carrying the final RRF `order`. The TUI appends
  batches deduped by `normalize_url` (same key the SPA uses) and marks late entries that the
  final order would have ranked above the visible cut. Dropping the receiver on retype is
  free — the spawned flight still finishes and warms the cache.
- Suggestions: `Store::suggest` (prefix/frecency) on a debounce while typing.
- Open: `webbrowser` to the system browser. Yank: OSC52 escape (clipboard over SSH; no X11
  dep) — terminal ignores it harmlessly when unsupported.
- `ClientKind::Cli` labels searches `cli` in `search_log`; a `Tui` variant is a follow-up if
  segmentation matters.

## MVP acceptance (this PR)

- `cargo build -p cauce-cli` produces `cauce tui` behind default features; the minimal
  `--no-default-features --features mcp` build still excludes it.
- `cauce tui` opens the UI; typing a query and hitting enter streams results in.
- Results dedupe by normalized URL; engine badge + cache/live badge + elapsed shown.
- `o`/`Enter` opens the selected result in a browser; `y` yanks via OSC52; `q`/Esc quits.
- Suggest dropdown renders `Store::suggest` matches while typing.
- `ratatui` TestBackend unit tests cover dedupe + first render states.
- `mise run validate` green.

## Later phases (own issues)

- Answer mode: `a` surface streaming `AnswerFrame` (`step`/`delta`/`sources`/`done`), `done`
  rendered as markdown via termimad; `related_questions` as one-key follow-ups.
- `RemoteBackend` (`--remote <url>`): `/api/search/stream` + `/api/suggest` (+ `/api/answer`)
  into the same frame types — the public-instance client story.
- Archive/history panes (LocalBackend `Store` reads), admin panes, `ClientKind::Tui` label,
  engine pins/safesearch/time-range controls.
