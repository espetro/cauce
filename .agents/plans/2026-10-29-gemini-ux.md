# UX-1 — Gemini-class AI UX for cauce

Parent: `../2026-09-21-v3-rust-core.md`. Wave file: `v3/wave-8-gemini-ux.md`.
Research basis: user session 2026-10-29 on v0.8.1 (follow-up messages broken, sources
buried under the answer, prompt at the very end, nav not minimal).

Iteration 9. Priority P1. Target release: **v0.9.0**.

## Problem statement

On v0.8.1 the AI surface underperforms against the market (Gemini, ChatGPT, Perplexity):

1. **Follow-up messages do not work.** The thread path exists end to end
   (`features/answer/thread.svelte.ts:171-181` → `POST /api/answer` with `history[]` →
   `handlers/answer.rs:40-98` replays it), but the SPA rewrites the URL to
   `/answer/{log_id}` — **outside the `/app` mount**, where the SPA is not served. A reload
   or back/forward lands on the server-rendered page with no hydration path back into the
   SPA (`GET /api/answer-log/{id}` exists but is `.admin()`-gated and the SPA never calls
   it). A second defect: the server caps `history` at 20 turns / 64 KiB and answers `400`
   `bad_request`, which the UI surfaces as a generic stream failure.
2. **Sources dominate the answer.** The source list renders inline after the whole answer
   (`features/answer/SourceCard.svelte`), so the composer sits below the fold after a long
   source list. There is no collapsed or side-panel presentation.
3. **The composer is at the end.** First load shows the omnibox; mid-conversation the
   follow-up composer is the last element (`features/answer/FollowupComposer.svelte`).
4. **Search results are not minimal.** The results page carries a cache-details
   collapsible, a separate stream-status line, and an assist card, on top of bordered rows.
5. **The nav is not minimal.** A full-width header with 4 primary links left and 4 operator
   links + settings + theme + a `more` dropdown right (`app/TopNav.svelte:60-124`); the
   operator links collapse below 700px, the primary links just wrap.

## Goal

Make the AI surface a **conversation** (not a form + a result dump), make search minimal,
and make the chrome minimal — without forking the layout into two divergent designs, and
without changing the visual theme.

Non-goals: no theme/brand refresh (Q14 — tokens and typography stay as they are); no
`Cmd+K` palette; no new Playwright e2e suite in this wave; no landing-page redesign
(the cauce.fyi landing stays as it is — audit only, step UX-08).

## Settled inputs (from the 2026-10-29 session)

- **One shell, two bodies.** Query always renders as a top-anchored prompt card; the body
  below it is either the result list (search mode) or the answer thread (AI mode). Same
  component tree, two body variants. No "traditional vs AI" layout fork.
- **One composer component, position by state.** Empty thread → top-anchored; thread with
  turns → sticky bottom. The first question stays visible at the top of the thread.
- **Sources = side panel** (desktop) / **bottom drawer** (mobile). Panel scope follows the
  selected turn; header shows `Sources · turn N/M`. Inline citation chips are a follow-up
  (step UX-05 ships the panel + the chips that open it; chip-in-text anchoring is later).
- **Nav split.** Left: logo (home) · Search · Answer · History. Right: theme toggle ·
  waffle menu (phosphor `squares-four` — the existing icon library; no lucide dependency)
  holding Dashboard, Archive, Engines, Cache, Audit, Settings, Docs. Admin-only entries
  stay hidden unless `capabilities.flags.adminSurface`.
- **Search minimalism.** Single column, hairline rows (favicon · title · host · 2-line
  snippet), one muted meta line (`12 results · 140 ms · cached`). Drop the cache-details
  expander, the separate stream-status line, and the assist card from the results page
  (assist stays reachable in AI mode).
- **Thread persistence = server-authoritative threads + client-authoritative live
  transcript** (Q8). This is what ChatGPT/OpenAI, TanStack AI (documented default),
  CopilotKit and the Microsoft Agent Framework converged on; client-local storage is the
  unauthenticated fallback, not the target. See §3 for the exact shape.
- **Mobile.** Sources = bottom drawer (drag to dismiss, ≤80vh). Waffle menu = full-screen
  sheet. Left nav group stays visible at 360px.
- **Landing.** cauce.fyi's landing is the reference and stays unchanged. The binary's
  rust-embed build has never had it (`VITE_CAUCE_LANDING` is a Pages build-time flag,
  `web/src/spa/lib/flags.ts:16`) — see UX-08, which makes the landing locally previewable
  without changing what ships.
- **Testing.** vitest for the new state logic; manual playwright-cli walkthrough for the
  layout golden paths. No new Playwright suite this wave.

## Architecture

```
crates/cauce-core/src/store.rs        AnswerThreadRow, Store::upsert_thread / list_threads / get_thread / delete_thread
crates/cauce-core/src/ai/answer.rs     AnswerBody gains `thread_id?`; the loop persists the completed turn
crates/cauce-store-sqlite/migrations/  0006_answer_threads.sql
crates/cauce-server/src/handlers/      threads.rs (list/get/delete), answer.rs (persist on done)
crates/cauce-server/src/routes.rs      /api/threads rows (+ the route-table conformance test)
crates/cauce-server/web/src/spa/
  app/TopNav.svelte                    left group · right group · waffle menu
  features/answer/                     AnswerThread.svelte (thread body), SourcesPanel.svelte, SourcesDrawer.svelte
  features/search/                     ResultRows.svelte (hairline rows), MetaLine.svelte
  lib/api.ts                           postAnswer / listThreads / getThread / deleteThread
```

**Thread ownership.** A thread row carries `owner`: in local mode the single local user
(`"local"`), in public mode the bearer token's identity (hashed — never the raw token).
`Store` reads filter by owner, so a public instance never leaks another user's
conversation. This is the same isolation rule TanStack documents: *isolate by id, then
authorize the user before you load*.

**Two layers, one source of truth.** The SPA keeps the live transcript in memory (it
already does) and sends the full `history[]` on every turn (it already does). The server
persists the completed turn on `done`. On reload the SPA hydrates from
`GET /api/threads/{id}`; if that call fails, a localStorage copy of the current transcript
is the fallback (Q18). The URL becomes `/app/answer?thread=<id>` — **inside** the SPA
mount, so back/forward and reload stay in the app. The existing server-rendered
`/answer/{id}` page keeps working for durable single-answer links, and `answer_log` stays
as the "share this answer" artifact.

**Compatibility.** `POST /api/answer` without `thread_id` behaves exactly as today
(client-owned thread, no persistence). With `thread_id`, the server upserts the thread and
returns the id in the `done` frame. The 20-turn / 64 KiB `history` cap gets a **client-side
counter and a specific error message** instead of a generic failure.

## Risks

- **Thread storage is a schema change.** Migration `0006_answer_threads.sql` appends
  (never edits a shipped migration). `Store` trait changes ripple to the Postgres
  `later/` work and the conformance suite — the trait method set is the contract, so UX-01
  updates `crates/cauce-core/src/conformance/` in the same PR.
- **`answer_log` vs thread duplication.** The thread transcript and the per-run
  `answer_log` row overlap. `answer_log` stays the durable single-answer artifact; the
  thread is the conversation. UX-01 must not conflate them.
- **Panel + composer on one viewport.** The sticky composer and the side panel both claim
  the bottom/right edges on narrow screens. UX-04 must test both open simultaneously at
  390px.
- **Bundle size.** The landing sections and the panel add to an already 426 KB JS bundle.
  UX-03/UX-04 must not import the landing component into the app bundle.
- **Regression risk on the golden path.** Every step runs `mise run validate` (which
  rebuilds the SPA and diffs the committed `assets/spa/`) plus a replay-engine golden-path
  check before merging.
