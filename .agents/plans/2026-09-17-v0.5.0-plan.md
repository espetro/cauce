### JS budget derivation (local app profile)

Localhost SPA on 2026 desktop hardware. Desktop V8 parse + compile of 100 KB gz JS ~30-60 ms (one-off, cached thereafter via V8 code caching), well under the 100 ms RAIL "feels immediate" threshold. Comparable local-LLM apps (AnythingLLM, Jan.ai, LM Studio) ship multi-MB Electron renderers; 100 KB gz of web renderer is an order of magnitude lighter. [web.dev's "Your first performance budget"](https://web.dev/articles/your-first-performance-budget) explicitly allows 300 KB JS for a 2 s TTI on WiFi+desktop — 3× the proposed target.

Numbers from `bun run build` 2026-09-17:
- Today: 37 KB gz JS / 22 KB gz CSS (cap was 45 / 35; ~8 KB JS headroom)
- v0.5.0 projected: 49-59 KB gz JS / ~30 KB gz CSS (with multi-turn FSM + Zag + citation popovers + source rail + tools toggle + auto-title)
- Target 100 KB: leaves 41-51 KB headroom for v0.6
- Ceiling 150 KB: WARN at 130 KB before FAIL — recalibrate then

## 1. v0.5.0 scope (six atomic streams)

Each stream is a self-contained logical change with its own commit(s). Streams are written so they can ship in any order; the ordering below is a recommended dependency order.

### Stream 1: Architecture seam docs (ARCHITECTURE.md + DATAMODEL.md)

**Why**: owner wants explicit seams among SQLite <-> server <-> UI and strictly-typed FSM/DAG state on both sides. This is a deliverable, not a code change. Foundation for every later stream.

**Files**:
- `ARCHITECTURE.md` (new at repo root) — system design: layer responsibilities, allowed dependencies per layer, request lifecycle, state-machine boundaries.
- `DATAMODEL.md` (new at repo root) — every SQLite table, every column, every JSON field on the wire, every in-memory state machine (states + events + transitions), every URL-contract param.
- `ui/src/lib/states/` (new) — typed FSMs for the app's stateful primitives (combobox, dialog, popover, suggestions dropdown, mobile menu). One FSM per primitive, in `states/<name>.ts`, using the `useReducer` + discriminated-union shape from the FSM memo.

**Key claims to enshrine in ARCHITECTURE.md**:
- Layer rule: `ui -> server -> sqlite` only. `sqlite -> server` only via `oxe/cache.py` (single owner). No cross-layer imports.
- Server state lives in SQLite (cache, search_log, clicks, answers, config). Server has no in-memory FSMs longer than a single request — each request either completes or aborts.
- UI state lives in URL + `localStorage` + component-local stores. Two atoms in nanostores today (`$toasts`, `$route`); keep it to that. Other state stays in URL or `useReducer`.
- MCP is a peer of the HTTP API; both share the SQLite cache and `search_log`. No MCP-only state.
- Streaming AI endpoints (`/answer`) emit a closed event vocabulary: `step | delta | sources | done`. No new event types without updating DATAMODEL.md.

**Key claims to enshrine in DATAMODEL.md**:
- SQLite tables: `cache`, `search_log`, `clicks`, `answers` (and the `sqlite_sequence` implicit one). One row per write boundary.
- For every column: type, nullability, write paths, retention rule, indexing note.
- Every JSON response shape the SPA consumes: typed against `valibot` schemas in `ui/src/lib/schemas.ts`; cross-link schema to docs.
- Every URL-contract param: `q`, `p` (deprecated), `mode`, `settings`, `since`, `qf`, `suggest` (planned), `force` (planned). One row per param with allowed values + behavior.
- Every FSM: states + events + transition table + "exhaustive switch" enforcement (TS) + a `_exhaustive: never` branch per memo.

**Acceptance**: both files checked into root. `npm run check` (or `mise run check`) passes; lint clean.

**Effort estimate**: S (one dev, one day for the docs + `states/` skeleton).

### Stream 6: Multi-turn chat UI + strict chat FSM (Stream A+B+D)

**Why**: today's single-query AI surface (`useAnswer.ts`, `AnswerView.tsx`) doesn't allow follow-ups. v0.5.0 makes chat a first-class multi-turn surface.

**Files (server)**:
- `oxe/server/ai.py` — extend the `Message` type and SSE event vocabulary to support multi-turn (`conversation_id`, `parent_id` per turn; `thread.message.add` events). Keep the openai/anthropic SDK direct path.
- `oxe/sql/answers.sql` — extend `answers` table with `conversation_id TEXT NOT NULL DEFAULT ''`, `parent_id TEXT NOT NULL DEFAULT ''`. Add indexes for thread lookup.
- `oxe/sql/schema.sql` — schema migration.
- `POST /answer` — accept `conversation_id` + `parent_id`; on first turn, mint `conversation_id` and return it in `done`; on follow-ups, hydrate prior messages from `answers` (or a new `messages` table).
- New `GET /answer/{conversation_id}` to list turns (for the history pane).

**Files (UI)**:
- `ui/src/features/answer/useAnswer.ts` — replace with a chat-thread hook (`useChatThread`) that owns the message list, applies events via `useReducer` + discriminated-union events (see FSM memo), supports `send | stop | retry | branch | regenerate`.
- `ui/src/features/answer/AnswerView.tsx` — render a message list (user + assistant turns). Sticky input composer with Up-arrow recall, Shift+Enter newline, Esc stop.
- `ui/src/features/answer/MarkdownLite.tsx` — extend for citation popovers (Zag `popover`, see Stream 7) and `[n]` superscript linking.
- `ui/src/lib/states/chatThread.ts` (new, in `states/`) — typed FSM: states = `idle | streaming | awaiting-tool | done | error | stopped`, events = `send | delta | step | sources | done | error | stop | retry | branch`. Use the shape from the FSM memo's "Sketch: oxe combobox FSM" verbatim style. One `_exhaustive: never` per switch.
- `ui/src/lib/api.ts` — extend `search` / `answer` clients to carry `conversation_id` and `parent_id`.

**Commits** (atomic, this is the biggest stream):
1. `feat(sql): answers + messages schema for multi-turn threads`
2. `feat(server): /answer accepts conversation_id + parent_id, emits thread.message events`
3. `feat(ui): useChatThread hook with typed FSM`
4. `feat(ui): sticky pill composer + Up-arrow recall + Esc stop`

## 4. Open questions (owner must answer before commit 7 lands)

From the architecture audit + the research:

1. **What does "delete history" mean?** Clicks only (Option A) or also wipe `search_log` (Option B, the user mental model)? Drives Stream 2 scope.
2. **Keep `x-cache*` headers on `/search` HTML responses?** Yes (keep one SPA shell handler, add `FileResponse` headers) or no (drop the handler entirely)? Drives Stream 5 sub-step 2.
3. **Keep JSON 404 envelope for unmatched API paths?** Yes (add `@app.exception_handler(StarletteHTTPException)`) or no (plain 404)? Drives Stream 5 tests + behavior contract.
4. **AI mode logging**: log AI-mode queries into `search_log` so they show in dashboard aggregates? Drives Stream 3 + Stream 6 writer.
5. **`/cache` page row browser**: full row-by-row UI or just keep `/cache/stats` aggregate + Dashboard callout? Drives Stream 4 scope.
6. **Tools toggle default**: web-search-on by default for `/answer` (matches today) or off by default (chat-only mode)? Drives Stream 8.
7. **Auto-title LLM call**: on every response (extra tokens, extra latency) or only on first message of a thread (cheap)? Drives Stream 8.
8. **Tab persistence**: today's localStorage `oxe-mode` survives reloads. After Stream 3, do history-mode clicks override localStorage for that click only, or permanently? (UX question — probably per-click-only.)
9. **Multi-turn caching**: do follow-up turns share a cache key with the first turn (reuse the same web search results) or each turn is independent? Drives Stream 6 server.
10. **Branch / regenerate** for multi-turn (per chat-ui-patterns memo): ship in v0.5.0 or v0.6+? Drives Stream 6 sub-step 3 scope.

## 6. Risks + mitigations

| Risk | Mitigation |
|---|---|
| FastAPI 0.137+ APIRouter tree refactor breaks `router.routes` iteration | Grep `\.routes\b` across `oxe/` returned zero matches in audit. Safe. |
