# oxe v0.5.0: archive the exploration, rebuild on a constrained, gated foundation

## Context

`main` currently holds 54 commits of `feat/v0.4.0-web-ui` work. The retrospective that
preceded this plan found the cost was not in the features: it was in five cross-cutting
policies (daisyUI, no-useEffect, generated types, i18n, typed routes) applied *after* the
screens existed, costing 11,565 lines of churn (~30% of effort), on a branch where no
automated gate ever fired (zero CI runs, no hooks, 45% of the diff machine-generated,
33% rework rate).

The decision is to treat that branch as exploration, archive it, and restart `main` from an
empty history on a foundation where those five policies are commit-1 facts enforced by
scripts, not documents. The stack is deliberately narrow: React is brittle precisely because
it offers six ways to hold state, so this plan names exactly one approved way per problem and
makes the alternatives lint errors.

Verified current versions (2026-09-17): Vite 8.3.0, React 19.3.0, `@vitejs/plugin-react-swc`
4.3.3, `@swc/core` 1.16.2, `@tanstack/react-router` 1.170.38, `@lingui/*` 6.7.0 including
`@lingui/swc-plugin`, `@base-ui/react` 1.8.0, daisyUI 5.7.39, Tailwind 4.3.3,
`@xstate/store` 4.2.3, oxlint 1.83.0, valibot 1.5.0, FastAPI 0.138+ for `app.frontend()`.

Two corrections to the stack as originally sketched: `@xstate/fsm` is retired (successor is
`@xstate/store`), and Base UI ships as `@base-ui/react`, not `@base-ui-components/react`
(that package is frozen at `1.0.0-rc.0`).

### No Babel anywhere

The build is SWC end to end, and the linter is oxc. Both React Compiler and the Lingui macros
are first-party SWC features, so there is no Babel pass and no macro-vs-compiler ordering
problem to babysit:

- **Transform**: `@vitejs/plugin-react-swc` with `jsc.transform.reactCompiler: true` (needs
  `@swc/core` >= 1.15.43; >= 1.15.47 for `enableFunctionOutlining`). React 19 supplies
  `react/compiler-runtime` natively, so no `react-compiler-runtime` shim.
- **i18n**: `@lingui/swc-plugin` 6.7.0 in the same `plugins` array, replacing
  `@lingui/babel-plugin-lingui-macro`.
- **Lint**: oxlint's 22 native Rust React Compiler rules (`"plugins": ["react"]`,
  `categories.correctness: "error"`), not the `jsPlugins` bridge to
  `eslint-plugin-react-hooks`. Native means it runs at oxlint speed inside `mise run validate`.

`oxc-transform-react` 0.150.0 exists and is what `@vitejs/plugin-react` 6.1's experimental
compiler option uses, but oxc's own post calls the Vite integration experimental and the Rust
port unfinished (16 TODO markers, 57 Todo diagnostics). So: oxc for linting today, SWC for the
transform, and revisit `oxc-transform-react` for the transform once it drops the experimental
label. That swap touches one config block.

**The one fragility to gate:** `@lingui/swc-plugin` is a Wasm plugin and Wasm plugins are
locked to the `@swc/core` ABI. A `@swc/core` bump ahead of a Lingui release breaks the build.
`@swc/core` is therefore pinned exactly, not caret-ranged, and bumping it is a deliberate commit
that must pass `validate`.

## Decisions locked

| Question | Decision |
|---|---|
| Component layer | daisyUI 5 for looks (zero JS), `@base-ui/react` for behavior (focus, keyboard, portal) |
| State | URL first, then other non-opaque state, then useReducer FSM, then `@xstate/store` |
| Server state | TanStack Router `loader()`; SSE streams into a rung-3 reducer |
| History | `git branch -m main legacy`, keep the `v0.4.0` tag and PyPI release, orphan a new `main` |
| Search contract | SearXNG is the only canonical surface; Exa HTTP and MCP are thin frozen adapters over it |
| Python | basedpyright strict, no `dict` across module boundaries, no broad `except` outside one handler |
| Docs | every normative line carries an enforcement tag, and a test asserts the tag resolves |

## Target architecture

```

    searx.py         GET/POST /search  (canonical, the only extensible surface)

    mcp.py           exa_search + exa_user_history, unchanged wire shape, via exa.py

ui/
  src/routes/        TanStack Router file routes, one per screen spec
  src/lib/           schemas (valibot), api client (openapi-fetch), stores, fsm helpers
  src/components/    only components built ON TOP of daisyUI classes + Base UI parts
  src/locales/       Lingui catalogs

  e2e/               Playwright + the .md adapter, driven by URL checkpoints
```

`app.frontend(path, directory="dist", fallback="index.html")` (FastAPI 0.138, June 2026)
replaces the entire legacy `oxe/server/ui_dist.py` plus static-mount plus catch-all stack.
Path operations still win; the frontend is only consulted when no route matched.

### What is lifted from `legacy` rather than rewritten

Lift with its tests: `cache.py`, `config.py`, `devlog.py`, `stats.py`, `sql/`, the engine
adapter logic inside `exa_compat.py`, the `SearchBackend` Protocol and timeout/fanout
machinery in `backends.py`, `registry.py`.

Rewrite: `ai.py` (the retro logged two parse defects and a silently-disabled `tools` kwarg),
`cache.py`'s blanket `except sqlite3.OperationalError: pass` migration, and the whole of
`oxe/server/` HTML-and-SPA-serving layer (superseded by `app.frontend()`).

Discard: all of `ui/`. The v0.4.0 UI remains checked out on `legacy` as a visual reference.

### The search contract

Canonical model is the SearXNG response: `query`, `number_of_results`, `results[]`
(`url`, `title`, `content`, `engine`, `engines`, `score`, `category`, `publishedDate`,
`thumbnail`), `answers`, `corrections`, `infoboxes`, `suggestions`, `unresponsive_engines`.
Request side: `q`, `pageno`, `categories`, `language`, `time_range`, `safesearch`.

`GET|POST /search` in SearXNG format is the one canonical, extensible surface. Exa is
compatibility only, kept because your global agent wiring (Claude Code, Hermes, maki) already
points at this app: `oxe/api/exa.py` holds exactly two pure functions,
`exa_request_to_query()` and `searx_response_to_exa()`, and `oxe/api/mcp.py` calls them to keep
`exa_search` and `exa_user_history` working unchanged. No new capability is ever added to the
Exa shape; it is frozen at Exa's published schema, which we do not control anyway, so it cannot
drift out from under us.

Three rules in the adapter are logic rather than shape, and a round-trip property test pins all
three:

1. `numResults` maps onto `pageno` plus a slice; the engine page size is an engine property.
2. A non-empty `unresponsive_engines` with empty `results` raises `BackendError`. It is never
   returned as an empty Exa result set. The legacy `backends.py` docstring already forbids this
   conflation, and it is the single most common SearXNG client bug.
3. Cache identity is computed on the canonical query, so both entry points share one cache row.

## The API contract is typed in both directions

Types first, parsers second. The generated types are the primary test surface, and runtime
validation only appears where a type cannot reach.

Legacy covered one direction badly and the other barely. Measured against its `openapi.json`:

| | Count |
|---|---|
| Operations | 22 |
| Operations with **no typed 200 response schema** | **11** |
| Mutating operations with **no request body schema** | **3** |
| Routes declaring `response_model` | 11 of 22 |

`GET /suggest` is published as `array of {}`. `GET /search`, `GET /history`, `POST /answer` and
`POST /history/delete` publish nothing at all. So the generated TS types described roughly half
the contract, and the half they described was the half least likely to break.

**Layer 1, types (compile time, zero runtime cost).** Every operation declares both ends:

- `response_model=` on every route. `-> dict` and `-> list` are basedpyright errors under the
  data ladder, which removes the mechanism that produced the 11 gaps.
- A pydantic body model on every POST, PUT and PATCH.
- Query parameters as an `Annotated[..., Query()]` model so they land in the schema too.
- `openapi-typescript` turns that into `types.gen.ts`, and `openapi-fetch` types the request
  body, the query, the path params and the response at each call site from the same `paths`
  object. Both directions come for free once the spec is complete, which is why completeness is
  the thing to gate.

**The gate**: `tests/test_openapi_coverage.py` walks every operation and fails unless the 200
response resolves to a component `$ref` (not a bare `object`, `array` or nothing) and every
mutating method has a `requestBody` `$ref`. It is about fifteen lines and it makes the
"half-covered contract" state unreachable rather than merely discouraged.

**The SSE hole.** `POST /answer` is `text/event-stream`, so OpenAPI does not describe its frames
and no generator can type them. That is precisely where the retro found two parse defects. Fix:
declare the frame union as pydantic models, register them as OpenAPI component schemas
explicitly even though the endpoint does not return JSON, and generate TS types from them like
everything else. The most complex payload in the app stops being the only untyped one.

**Layer 2, parsers (runtime, only at boundaries types cannot cross).** Exactly three places
get a valibot schema:

1. URL search params, via TanStack Router `validateSearch`. The browser can send anything.
2. `localStorage` codecs. The disk can hold last release's shape.
3. SSE frame parsing, since the transport is text.

Everywhere else is types-only. And where a valibot schema mirrors a generated type, a type-level
assertion (`const _: Equal<InferOutput<typeof S>, components["schemas"]["X"]> = true`) pins
them, so the parser cannot quietly diverge from the contract. Legacy's hand-written
`ui/src/lib/schemas.ts` was an independently authored second copy of the wire format with
nothing holding the two together.

## Python: the same treatment

The frontend gets narrowed because React offers six ways to hold state. The backend needs it
for the mirror-image reason: Python offers no resistance at all. Measured on `legacy`:

| Symptom | Count | What it cost |
|---|---|---|
| `model_config = {"extra": "allow"}` on every wire model | all 18 in `server/schemas.py` | a dropped or typo'd field is accepted and silently discarded. This is the `PUT /settings` bug that wiped `base_url` for 10h |
| `uv.lock` gitignored (lines 40 and 56 of `.gitignore`) | 2 rules | no reproducible install; local and CI resolve independently |
| bare `dict` in a signature | 61 | the wire format was never a type, so nothing could check it |
| broad `except` | 49 | including `except sqlite3.OperationalError: pass` in the cache migration |
| `Any` | 14 | |
| ruff ignore entries | 21, including `BLE001` and four `TRY` rules | the linter was configured to not report the above |
| type checkers configured | 0 | a stale `.mypy_cache` is the only trace anyone ever ran one |
| Python formatter | none | hence the 1,461-line reformat landing 32 seconds after the commit that should have carried it |

Two ladders, mirroring the frontend's state ladder.

### The data ladder: no `dict` crosses a module boundary

1. **Wire models**: pydantic `BaseModel` with
   `model_config = ConfigDict(extra="forbid", frozen=True, strict=True)`. `extra="forbid"` is
   the single highest-value change on this list: it converts a whole class of silent
   field-drop bugs into a 422 with the offending key named.
2. **Internal values**: frozen dataclasses or `NamedTuple`.
3. **`dict[K, V]`** only for genuine homogeneous maps, always parameterised.
4. **`Any` is banned**, by `ANN401` and basedpyright's `reportAny` / `reportExplicitAny`.

The payoff compounds: accurate models mean accurate `openapi.json`, which means accurate
generated TS types, which is the one contract that did not drift in 48h last time.

### The error ladder: one broad handler, everywhere else is typed

1. Domain modules raise typed exceptions declared in `oxe/errors.py`.
2. Every `except` names concrete types. A handler either re-raises or logs with context.
   `except ...: pass` is a lint error, not a review comment.
3. Exactly **one** broad boundary handler, in `oxe/api/errors.py`, registered as a FastAPI
   exception handler, mapping domain exceptions onto `ErrorEnvelope`.
4. The ruff ignore list **starts empty**. `BLE001` and the `TRY` set are on. Every future
   addition needs an inline comment saying why.

### Python gates

| Gate | Tool | What it catches that a human did not |
|---|---|---|
| Types | **basedpyright 1.40.1, strict** | the 61 dicts, the 14 `Any`s, unchecked `None` paths |
| Lint | ruff 0.16 with an expanded `select` and an empty `ignore` | broad excepts, blocking calls in async, naive datetimes |
| Format | `ruff format --check` | reformat-churn commits |
| Contract | **schemathesis 4.27** against `openapi.json` | payloads the handler accepts but the spec forbids, and vice versa |
| Properties | **hypothesis 6.168** | Exa round-trip, cache-key stability under reordering |
| Resources | `filterwarnings = ["error::ResourceWarning"]` | the three connection leaks fixed by hand, one of them twice |
| Determinism | `pytest-randomly` | order-dependent tests, before they become flaky in CI |
| Reproducibility | commit `uv.lock`, `uv sync --frozen` in CI | drift between your machine and the runner |
| Size | `C901` complexity limit, `PLR0913` arg limit | the 642-line `ai.py` that hid two parse defects |

ruff `select`: `E, W, F, I, B, SIM, RUF, C4, UP, BLE, TRY, ANN, ASYNC, S, PT, DTZ, PTH, LOG, G,
TID, ERA, FBT, N, C90, PL, RET, ARG, EM, ISC, PIE, SLF, INP`.

`ASYNC` earns its place specifically: `ddgs` is blocking and the search path is the hot path.
The rule is that every sync engine call goes through `asyncio.to_thread`, and `ASYNC2xx` fails
the build when one does not. Legacy already does this ad hoc in `ai.py` but not in
`backends.py`, which hand-rolls `ThreadPoolExecutor` in three places.

**Why basedpyright** over the alternatives: pyright-family narrowing is the best fit for
pydantic and FastAPI, and basedpyright adds exactly the rules that target this codebase's
failure mode (`reportAny`, `reportExplicitAny`, `reportUnknownMemberType`). It installs under
`uv` via `nodejs-wheel-binaries`, so no system Node. mypy 2.3 is a fine second choice. Astral's
`ty` is fast and will likely win eventually, but at 0.0.81 it is too young to be a merge gate;
revisit at 1.0, when swapping it in is a one-line mise task change.

## The frontend rules (commit 1, not commit 40)

One approved answer per problem. Anything in the right column is an oxlint error or a
missing dependency, not a code review comment.

| Problem | Approved | Banned |
|---|---|---|
| Routing | TanStack Router, file-based, `loader()` for data | any `useEffect` fetch |
| URL state | `validateSearch` with a valibot schema (Standard Schema, no adapter) | hand-parsed `useSearchParams` |
| Screen state | `useReducer` over a discriminated union with an exhaustive `never` default | `useState` chains for multi-step flows |
| Global state | `@xstate/store`, hard cap of 3 stores, enforced by a test | context providers, jotai, redux |
| Server state | router `loader()`; SSE into a rung-3 reducer | `useEffect` + `setState` |
| Wire types | `openapi.json` -> `openapi-typescript` -> `openapi-fetch` | hand-written response interfaces |
| Looks | daisyUI class names | raw Tailwind layout soup, custom CSS files |
| Behavior | `@base-ui/react` parts | hand-rolled focus traps, portals, comboboxes |
| Copy | Lingui macros, catalogs under `src/locales/` | any literal in JSX |
| Icons | `unplugin-icons` + Lucide | inline SVG, other icon sets |
| Memoization | React Compiler | manual `useMemo` / `useCallback` |

The daisyUI + Base UI split has one sentence of doctrine: **if it is looks, it is a daisyUI
class; if it is focus, keyboard or portal, it is a Base UI part.** They compose on the same
element via Base UI's `render` prop.

### The state ladder

Pick the highest rung that can hold the state. Going lower requires a note in the PR.

1. **URL.** Anything a QA agent should reach by link: query, cursor, mode, which dialog is
   open, filters, and the forced QA states. Typed by `validateSearch`.
2. **Other non-opaque state.** `localStorage` behind a valibot codec, uncontrolled inputs read
   via `FormData`, router loader cache. Testable without mounting React.
3. **`useReducer` FSM.** Discriminated union state, exhaustive `never` check. Reducer is a pure
   function, unit tested with no renderer. This is where SSE streaming state lives.
4. **`@xstate/store`.** Theme and toasts. Three stores maximum.

## Docs and memory: rules that cannot silently rot

The retrospective's central finding was that documented rules drifted and scripted rules did
not. So the docs get a mechanism rather than a proofread.

**Every normative line carries an enforcement tag.** Each `AGENTS.md` splits into two sections:

- **Enforced** rules, each ending in `[gate: <mise task or script path>]`.
- **Conventions**, explicitly not gated, which reviewers may cite but which never block.

`tests/test_agents_rules.py` parses every `[gate: X]` across all `AGENTS.md` files and asserts
X resolves to a real `mise.toml` task or an existing script. A rule whose gate is deleted turns
red. A rule that cannot be tagged is either automated or moved to Conventions, and the honesty
of that split is the point: it makes the unenforced surface visible instead of pretending the
whole document is binding.

**Single source per fact**, with the copy that survives named explicitly:

| Fact | Lives in | Everywhere else |
|---|---|---|
| URL param contract | the route files' `validateSearch` schemas | a generated table, not a hand-written one |
| Size budget numbers | `ui/scripts/size-budget.ts` | referenced by name, never restated |
| Endpoints, env vars | `README.md` plus `openapi.json` | `tests/test_docs_endpoints.py` pins them |
| Approved libraries | `ui/package.json` plus `.oxlintrc.json` | `ui/AGENTS.md` links, does not list versions |
| Screen behavior | `.agents/docs/screens/<screen>.md` | each has a matching `tests/e2e/<screen>.md` |

Written in wave 1, before any screen, because writing them in wave 5 is how they became a
description of code that had already moved on:

- Root `AGENTS.md`: layout, tooling, the commit and backlog rules, the GitHub Project URL.
- `oxe/AGENTS.md`: the data ladder and the error ladder, with gates.
- `ui/AGENTS.md`: the approved-versus-banned table, the state ladder, the daisyUI-plus-Base-UI
  doctrine in one sentence, the Lingui rules. Explicitly **not** carried over from legacy: it
  was amended 11 times to match code that had already changed, it restates the size budget, and
  its own text contains the instruction "keep the two lists in sync", which is the failure mode
  named as policy.
- `tests/AGENTS.md`: the test taxonomy (unit, property, contract, e2e) and the rule that a
  screen spec without an e2e checkpoint file is incomplete.
- `.agents/decisions.md`: seeded with every decision in this plan, so the next session does not
  re-litigate the stack. Legacy's version captured none of roughly eight real decisions.
- `.agents/MEMORY.md` plus `.agents/notes/2026-09-17-velocity-retro.md`: the retro findings,
  carried forward so a future restart does not rediscover them.

## Day-0 gates

These land before any screen. Each one is the deterministic version of a rule that drifted last
time.

1. **Gate parity.** CI runs `mise run validate` and `mise run validate:full` and nothing else.
   No bespoke CI script, which is how the old `ci.yml` ended up curling a deleted path.
   Triggers on `branches: ['**']`, not just PRs.
2. **`.githooks/pre-push` -> `mise run validate`**, installed by `mise run hooks:install`,
   documented in the README quickstart.
3. **oxlint with its native React Compiler rules.** `"plugins": ["react"]` plus
   `categories.correctness: "error"` turns on the 22 Rust-native Rules of React checks,
   including `set-state-in-effect`, rules-of-hooks, purity, immutability, refs and
   preserve-manual-memoization. No `jsPlugins` bridge, no second ESLint pass. Plus a
   `no-restricted-syntax` rule banning `useEffect` outside an allowlisted `src/lib/effects/`
   directory, so every remaining effect is a reviewed, named exception.
4. **`"strict": true`** plus `noUncheckedIndexedAccess`, with `scripts/` inside a tsconfig
   `include`. Last time the guard scripts were in no tsconfig and shipped broken imports.
5. **Generator gates.** `mise run validate` fails if `openapi.json`, the generated TS types, or
   the Lingui catalogs are stale, each as `<generate> && git diff --exit-code <path>`. This is
   the one pattern that did not drift in 48h last time; it now covers three facts instead of one.
   Paired with `tests/test_openapi_coverage.py`, so the spec cannot be fresh *and* half empty,
   which is the state legacy was in: 11 of 22 operations with no typed response.
6. **Determinism fixtures before screens.** `force=error|ai-off|empty` and `suggest=1` are
   implemented in the fetch layer in wave 2, before any real screen exists. Last time they were
   specified on day 1 and never built, so two days of QA ran by killing the backend.
7. **`tests/e2e/`** with Playwright plus the markdown adapter, one checkpoint file per screen
   spec, driven by URL deep links. Wired into `validate:full`.
8. **Size budget with a measured floor.** Wave 1 builds a hello-world of the real stack and
   records the actual gz floor. Ceiling 200KB gz, target derived from the measured floor, and
   the number lives in `ui/scripts/size-budget.ts` only. No document restates it.
9. **`filterwarnings = ["error::ResourceWarning"]`** in pytest config, and `tests/conftest.py`
   redirecting `OXE_CACHE_DIR` and `OXE_CONFIG_DIR` before import, from the first test.
10. **basedpyright strict** plus `ruff format --check` plus the expanded ruff `select` with an
    empty `ignore`, all inside `mise run validate`. Turning these on at commit 1 costs nothing;
    turning them on at commit 40 is the retroactive-policy trap that cost 30% of last effort.
11. **`uv.lock` committed and `uv sync --frozen` in CI.** Legacy gitignored it twice, so no two
    installs were the same.
12. **`tests/test_agents_rules.py`**, so a documented rule whose gate disappears turns red.
13. **Branch pushed and PR open from commit 1**, so gates 1 through 12 are real.

## Waves

### Wave 0: archive and reset
1. `git branch -m main legacy && git push -u origin legacy`. Confirm the `v0.4.0` tag and the
   GitHub release survive. PyPI 0.4.0 is untouched.
2. `git checkout --orphan main`, clear the index, and build the first commit from scratch:
   `pyproject.toml` (version 0.5.0), `mise.toml`, `.gitignore` (with `dist/`, `dist-ssr/`,
   `__pycache__/`, no build output ever tracked, and **`uv.lock` tracked**), `LICENSE`, a stub
   `README.md`.
3. Un-ignore plans repo-locally with `!.agents/plans/` in `.gitignore`, since the global
   `~/.gitignore-global` silences them and made 1,639 lines of planning unreviewable.
4. `git push -u origin main --force-with-lease`, open the PR-less trunk, set branch protection
   requiring the `validate` check.

### Wave 1: gates, rules and skeleton, no features
5. Land every day-0 gate with an empty app: FastAPI with `/health` only, Vite 8 + React 19 +
   `@vitejs/plugin-react-swc` with `reactCompiler: true` + TanStack Router with one route,
   Lingui via `@lingui/swc-plugin` with one message. Pin `@swc/core` exactly.
6. Land the Python gates against that same empty app: basedpyright strict, ruff with the
   expanded select and empty ignore, `ruff format`, `uv.lock` committed, pytest config with
   `ResourceWarning` escalation and `pytest-randomly`.
7. Measure the gz floor of the skeleton, write it into `size-budget.ts`, set the ceiling.
8. **Verify the SWC pipeline composes**, since the docs do not state plugin order relative to
   `reactCompiler`: put a Lingui `<Trans>` macro inside a component the compiler will memoize,
   build, and assert the emitted chunk contains the extracted message id and a
