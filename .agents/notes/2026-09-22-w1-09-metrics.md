# W1-09 metrics implementation notes (2026-09-22)

Findings worth keeping for W1-06/W1-07/W2 follow-ups:

- `opentelemetry-prometheus` 0.32 unconditionally appends `_total` to monotonic sums and a
  unit suffix (`ms` -> `_milliseconds`) to instrument names. `MetricsHandle` uses
  `.without_counter_suffixes().without_units()` so the settled names (`oxe_*_total`,
  `oxe_*_ms`) land verbatim; do NOT re-add `.with_unit("ms")` on instruments.
- `oxe_core::Metrics::default()` is deliberately unbound: it resolves `global::meter("oxe")`
  on first record, so engines/pipelines built before `MetricsHandle::new` (inside
  `AppState::new`, which also installs the global provider) still report. Cost: two tests in
  one binary sharing the global provider can race the binding; `tests/metrics.rs` therefore
  holds a single test.
- `oxe_cache_entries` is an observable gauge over an `AtomicU64` cell refreshed in the
  `/metrics` handler and by a 30 s task: OTel callbacks are sync and cannot await the async
  `Store`.
- Stats split of truth: store persists `engine_health` + `search_log` (day series stay there);
  the metrics module's process-global `StatsRegistry` (512-sample rolling windows) feeds
  `StatsSnapshot::merge_metrics` for `engines[]` percentiles/reliability and `admission`.
- W1-07 hooks ready: `Metrics::record_admission_wait/rejected` and `record_stale_served`;
  `record_breaker_state` accepts real `BreakerState` once W1-06 tracks it.
- OTLP metrics exporter needs a tokio runtime at build time (tonic channel worker), same as
  the span exporter: `metrics.rs::otlp_reader` mirrors `observability::otlp`'s owned-runtime
  pattern and is never fatal.
