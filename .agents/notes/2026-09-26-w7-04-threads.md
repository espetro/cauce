# W7-04 conversation threads on `/answer`

- Thread state is client-passed `history` (`[{role, content}]` pairs) on `AnswerBody`;
  `AnswerRequest.history` replays it ahead of `q` as user/assistant ChatMessages.
- Multi-turn requests skip the `answers` cache on both sides — the key preimage is `q`
  alone, so a read could replay turn 1 at a follow-up and a write would poison
  single-turn lookups. `cacheable = req.history.is_empty()` gates both paths.
- `history` is validated at the route (≤20 turns, strict user/assistant pairs ending
  on assistant, ≤64 KiB total, `deny_unknown_fields` on `AnswerTurn`) — Anthropic
  hard-requires the alternation, and a malformed replay should 400, not 500 upstream.
- `history` + `context_results` together → 400; assist stays single-turn.
- Page: one `.answer-turn` per exchange cloned from `#answer-turn-tpl` (class-scoped
  queries; turn 1 keeps the SSR ids for the existing markers). Source cards are
  `src-<turn>-<n>` so `[n]` citations anchor to their own turn's list.
- The system prompt gets a `THREAD_PROMPT_SUFFIX` on multi-turn requests so the
  model knows earlier `[n]` markers indexed their own turns' sources.
- wiremock mount order trap: `up_to_n_times(2)` on the same fixture lets ONE request
  consume both mounts — interleave single-use mounts when scripting multi-call loops.
