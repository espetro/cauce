# W2-02 history page (issue #34, PR #135)

- `/history` is the same handler as `GET /api/history`; `Accept: text/html` switches to the Askama renderer. `history_inner` takes a `default_limit` param so the page caps at 200 while the API keeps its own default.
- Row `source` is render-time state, not `search_log.source`: batched `Store::cache_states(keys)` (one `IN` query, expired rows included) then `cached · <age>` / `cached · expired` / `network · t<n>`. A second identical search retro-marks the first row cached; `history_source_tracks_live_cache_state` covers it.
- `cached=1` filter is an `EXISTS` over unexpired `cache_entries` applied in `list_history` and `history_stats`; checkbox state and `clear` link derive from the same parsed filter.
- Clicks join to search rows by `query_hash` at render; orphans become `(click only)` rows. `DELETE /api/history/{id}` audits `history.delete` actor `ui` and must not touch `cache_entries`.
- Adding a `Store` trait method ripples into every test stub (`cauce-core/tests/support`, `observability/tests.rs`); adding a `HistoryFilter` field ripples into every struct literal (conformance, mcp handler, mcp tests).
- `mise run validate` runs fmt/clippy/deny/check:features/test in parallel against the shared CARGO_TARGET_DIR; fmt fails fast while others wait on the cargo lock, so run `cargo fmt --all` before validating.
- Footer request id must be the full uuid (inherited template abbreviated it; rubric checks selectability).
