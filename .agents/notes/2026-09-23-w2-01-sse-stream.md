# 2026-09-23 W2-01 SSE search stream

Issue #33 added progressive search results over SSE.

1. The core stream uses the same cache, singleflight, breaker, timeout, persistence, and logging paths as ordinary search. Its receiver is detached from the HTTP connection so a dropped client does not strand the flight.
2. `results` events use engine completion order. `meta.order` remains the canonical RRF order, with stable tie breaks based on configured engine order. The page keeps the arrival order and reports later items that would rank above earlier ones.
3. `SearchMeta.engines_skipped` is serde defaulted so stored response payloads from before W2-01 still decode.
4. `/api/search/stream` is implemented and mounted additively while `CURRENT_WAVE` remains 1. Other W2 routes are still in parallel and are not required by this step.
5. The screen spec, rubric, and references exist. No baseline screenshot was found in the screen docs, and a separate evaluator was not available in the delegated environment. Manual Playwright CLI checks passed after the main favicon route was rebased.
6. Push uses a pre push hook that invokes `mise run validate`. Wait for the owner’s serialized validation slot before pushing the branch.

## Round 1 review fixes (PR #137)

1. F1: the pin check moved out of the spawned stream task. `search_stream` is async and returns `Result`; `validate_pin` is public so `GET /search?stream=1` can render a real 400 without opening a stream. Mid-flight failures stay terminal SSE `error` events.
2. F2: streamed results carry `key = normalize_url(url)` and `meta.order` lists the same keys. The page dedupes on `key`, tags articles with `data-key`, and hides whatever the final order did not keep.
3. F3: `strings::search` owns search page copy; the inline script interpolates a rendered `var S = {...}` JSON object.
4. M1: `client=ui|api|mcp[:<name>]|cli` fills `req.client` only when `X-Cauce-Client` is absent; invalid values are ignored. The page appends `client=ui` since EventSource cannot set headers.
5. M8: `<noscript>` explains the streaming shell needs JavaScript.
6. Deferred in the PR body: M3 retry_after_s in SSE errors, M4 EventSource reconnect re-execution, M5 duplicate engine ids, M6 cache-serve age/ttl in meta, M7 merged batch label, M9 decorative sse-close.
